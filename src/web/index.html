How the agent thinks

Perceive → Plan → Act → Observe → Respond

Every capability is a typed tool with a JSON schema and a read-only hint. The built-in concierge, a browser agent and an IDE agent all call the same tools through one executor — so every action is validated, attributed and visible on the shared canvas.

  1. 01 · Perceive

    Understand the ask

    Normalise the message and read context: where you are, what is on screen.

  2. 02 · Plan

    Pick a skill

    Match an intent — route, nearest facility, meeting fit, evacuation, workflow, checks.

  3. 03 · Act

    Call typed tools

    Inputs are schema-validated at the boundary; unknown tools and bad ids are rejected.

  4. 04 · Observe

    Read structured results

    Tools return envelopes with data or typed error codes — never stack traces.

  5. 05 · Respond

    Show, don’t tell

    The route appears on the plan and in 3D, with a full tool trace in the activity log.

Agent
Software that decides which actions to take to reach a goal, then takes them.
Tool
A named, typed capability the agent can call (e.g. get_directions).
Workflow
A predefined multi-step journey the agent runs end-to-end (e.g. new-joiner day 1).
MCP / WebMCP
Open protocols that let any compatible AI client discover and call these tools.
Guardrail
Schema validation, read-only hints, input caps and life-safety rules (no lifts in a fire).
Human-in-the-loop
People and agents edit the same state; every action is attributed and reversible.
